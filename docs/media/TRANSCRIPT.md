# Cipher 0.6.0: narrated walkthrough transcript

This is a guided interface demonstration, not a live inference or download benchmark. First-install views and prepared questions/edits are labelled illustrations. The disposable file save and two-test command result are real. Narration uses the installed macOS Samantha synthetic voice. No real credential, personal project, runtime download or model download is included.

## 00:00 — Download Cipher

Welcome to Cipher. This guide starts from downloading the app. You do not need to know how to code. Pause the video whenever you want. Some first-time setup views are illustrated examples.

_Capture note: Illustrated download guide._

## 00:12 — Choose your file

Open the latest release on GitHub and scroll to Assets. Choose the Mac DMG, Windows setup EXE, or the Linux package for your computer. Do not choose source code to use the app.

_Capture note: Installer choices; see written guide for platform requirements._

## 00:24 — Meet your workspace

Open Cipher after installing it. Your messages and replies appear in the middle. Files appear on the left. Models and downloads is near the model selector at the top.

_Capture note: Cipher 0.6.0 interface._

## 00:35 — Already have Ollama?

If you already have Ollama and a model, leave them installed. Open Models and downloads, then Installed models. Click Use this model. If it already says Selected, you are ready.

_Capture note: Existing local model; no model download._

## 00:47 — Starting from scratch?

For a new setup, open Local engine and choose Install local engine. Ollama is the engine that runs local models. Cipher can install its own internal copy, so a separate Ollama installer is not required.

_Capture note: Fresh-install illustration; no installation performed._

## 01:01 — First, the engine

Review the official engine download and choose Install this engine when you want it. Wait for it to finish, then click Start local engine. Installing the engine alone does not install an AI model.

_Capture note: Runtime review only; download not executed._

## 01:14 — Next, a model

Now open Get models. Enter the model ID you want, then choose Find model. The written guide gives qwen three colon four b as one example. Its suitability depends on your computer and the task.

_Capture note: Choose a model yourself; example ID shown in the guide._

## 01:27 — Review the download

Check the model name, license and available space. Choose Download this model and wait for completion. Then open Installed models and choose Use this model. Look for Connected in the chat window.

_Capture note: Review only; the example model was not downloaded._

## 01:39 — Ask something simple

Start with Ask mode. Type, Hello, explain what you can help me do using simple words. Press Enter to send. Shift and Enter adds a new line. The first model load can take longer.

_Capture note: Prepared question; not a live inference recording._

## 01:52 — Open your folder

Click Open project and choose a practice folder. Files appear in Explorer. Click a file to read it. You do not need to attach every file. The model can search the selected project.

_Capture note: Disposable practice project._

## 02:05 — Your first file

Make a new practice folder and open it in Cipher. Choose Build. Ask for a hello dot text file containing My assistant is working. Read the proposed filename and text, then choose Approve and save.

_Capture note: Prepared first-file request; real review and save controls._

## 02:18 — It really saved

Click hello dot text in Explorer to read what was saved. This is a real text file in the disposable practice folder. You do not need Python, a terminal, or programming knowledge for this first task.

_Capture note: Actual saved text file; no commands needed._

## 02:31 — Start with a plan

Ask gives explanations. Plan proposes an approach before changes. Build can propose edits and actions. For important work, ask for a plan first and read what it intends to change.

_Capture note: Prepared question; no AI-generated plan claimed._

## 02:44 — Review before saving

This prepared example shows the real edit review screen. Read the filename and proposed contents. Green lines are additions and red lines are removals. Approve and save writes the file. Reject leaves the proposal unapplied.

_Capture note: Prepared teaching edit; real approval controls._

## 02:59 — Check the saved file

After approval, the card says Saved and checkpoint created. Open the file in Explorer to inspect the result. Undo this save can restore earlier contents if the file has not changed again.

_Capture note: Actual save in the disposable practice project._

## 03:11 — Review a command

A code project may have tests. Read a proposed command before choosing Run command. If you do not understand it, reject it and ask for an explanation. The optional practice exercise needs Python three.

_Capture note: Actual command review; Python is optional for the beginner text-file task._

## 03:25 — Read real results

The practice project now reports two tests and O K. This is real output from the disposable example. A reply saying done is not proof. Read the results and check your project normally.

_Capture note: Real local test output: two tests passed._

## 03:37 — Inspect the result

The saved source now multiplies price by quantity. Your first task can be much simpler: ask for a hello dot text file in a new practice folder. The written guide explains every step.

_Capture note: Actual saved practice source._

## 03:49 — Give it a name

You can name your assistant. Open Settings, then Appearance. Enter a name and save. The sidebar and replies use it. This example uses Atlas. The installed application is still called Cipher.

_Capture note: Name setting illustration._

## 04:03 — Several models

Keep several models installed if you have enough disk space. Save named connections for local or cloud models. Choose one from the chat header. Keeping multiple models loaded uses extra memory.

_Capture note: Saved connection controls; API keys remain session-only._

## 04:15 — Extra tools, later

More tools opens plans, goals, resources, project memory, Git and external tool connections. You do not need to configure all of them on day one. Add the tools that help your task.

_Capture note: Workbench overview._

## 04:28 — Computer access

The Computer access switch lets your model request app, web and ordinary file actions. Review each proposed action. macOS permissions may need your direct approval. Turn access off when finished. The guide explains these steps.

_Capture note: Access remains off in this demonstration._

## 04:44 — Make it comfortable

Appearance offers light, dark and hacker themes. Change colour and the colour dots change the whole app palette. Choose a text size that is comfortable for you.

_Capture note: Shared appearance controls._

## 04:54 — Give me a coffee

Coffee keeps your computer awake while Cipher is open. The coffee and water animation says Thanks man, then returns to chat. Keep-awake stays on until you turn it off or quit.

_Capture note: Coffee effect; operating-system sleep boundaries still apply._

## 05:06 — You can take it slowly

Getting started reopens the tour whenever you are lost. Start with one reply and one small reviewed file. Then learn the advanced tools. The GitHub guide, transcript and printable handbook are there whenever you need them.

_Capture note: End of guide; no runtime or model was downloaded._
